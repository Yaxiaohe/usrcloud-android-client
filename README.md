# 有人云巡站（Android）

[有人云](https://www.usr.cn) 平台的第三方 Android 客户端：批量巡检设备、
自动截图归档、离线/数据陈旧告警、历史数据折线图。纯原生 Java + WebView，
APK 约 1.5 MB。

当前版本 **v0.39**（与 `versionName` / 界面「关于」页显示一致）。

> 本仓库是**干净版本**：`assets/accounts.csv` 只有表头，不含任何账号、密码、
> 登录缓存或巡检数据，也不含任何公司标识。装好后在「账号」页自己添加账号。

## 一、功能

- **巡站**：按账号批量拉取设备最新值，Android Canvas 直接画卡片图，4 路并发，约 0.3 s/台
- **状态判定**：`online` 数据新鲜 / `stale` 有值但过旧 / `offline` 无数据 / `blank` 采集异常
- **监控**：前台服务保活，按规则比对并推通知，离线/恢复都提醒，重复告警去重
- **历史**：自动采样落盘（值变了才写，稳定期 1 小时一次心跳），可查 6/24 小时折线
- **导出**：跑完自动打包 zip，走系统分享面板发出去
- **账号**：账号表可界面编辑，也可直接改原始 CSV

### v0.39 新增

**一、巡站结果按状态筛。**

结果卡上方加了一排统计：总数 / 在线 / 离线(无数据) / 自定义。点哪个数字，下方列表就只剩哪一类，
搜索词可以和筛选叠加（结果卡会写「搜 X · 在线」）。统计数字是**全部站点**的台数，不受搜索词影响，
所以「总数 = 在线 + 离线」当场能验算。口径只有一份 `filterPatrol()`：仪表数字、列表显示、
大图弹窗的翻页顺序、导出弹窗列出的图，四处共用，不会出现「按钮写 3 台、导出却是 5 张」。

**二、「自定义」筛选：按变量值筛。**

长按「自定义」（或点旁边的「设置条件」）可以配多条规则，形如「回水温度 < 30」：
变量名 / 比较符 / 数值，支持多条、支持「与/或」。变量值来自截图时那一轮的真实读数
（`Core.ResultItem.rows`，和监控页实时表同一份排序同一份数值），不是事后去问平台。
没有数值的旧结果按「不满足条件」处理。

**三、监控规则：变量名前面加 `=` 表示一字不差。**

以前「变量名」只能部分包含：想只看「进水温度」，填「温度」会把「风机化霜出水温度」也带进来。
现在默认仍是部分包含（平台把名字改成「进水温度T2」照样命中），前面加 `=` 就是完全一致。
输入框下面实时写「当前：部分包含 / 完全一致 / 片段匹配」，保存前后都能看清自己开的是哪种；
规则列表里也带出 `=` 前缀，不会以为没生效。带 `*` 的片段匹配保持原样，一个字没动。

顺带把两个标签的说明改准了：设备名那一栏原来写「写「某线路」= 名字里含某线路」，可实际不带 `*`
是精确相等 —— 照着填一条提醒都不会来（v0.21 修过匹配、漏了说明）。现在写明「写「某线路*」= 名字含」。

**四、巡站页重排。**

账号选择改成两列（四个账号原来占四行，把按钮顶到下面）；「巡站进度」移到控制区下面，
点完开始往下一眼就能看到跑到第几台；截图保存路径挪到整页最下面；完成提示写实测的跑完时刻
（`Core.finishedAt`，不用前端轮询时刻凑），重启后从本地缓存里还能读到。

### v0.38 修订（版本号不变）

**一、修「小程序里有数，监控页却全线离线、所有变量是 -」。**

平台对 `history` 接口有频控（实测返回 `status=5144` `Request frequency reached the limit`，`data` 直接给 null）。
原来的取数方式是一台设备发一次「最新值」请求：47 台就是 47 次，三个账号近百次，后半截必然被拒，
那些设备一条值都拿不到，于是被 `judge()` 判成离线。

改法：
- **先收齐变量点，再合并取最新值。** 每台先取一次变量点定义（拼出 `dataPointRelId`），
  然后把整个账号的点合成 1~2 次 `fetchLastBatch`。实测 47 台 1054 点一次返回 1048 条、0.9 秒。
- **分片从 400 改成 2000**（`Watch.LAST_CHUNK`）。限流按**请求次数**算，跟一次带多少点无关；
  400 一片时 47 台要发 3 次，3 秒一轮就是 60 次/分，这本身就是被限流的主因。
- **被限流后冷却 20 秒**（`Core.LIMIT_COOLDOWN_MS`、`markLimited()`、`waitCooldown()`），
  期间不再硬打接口。
- **这一轮没取到就沿用上一轮状态，不参与告警判定**（`DevState.fresh = false`），
  避免被限流一次就按旧状态反复报警。

**二、「平台说在线、却没读到值」不再判离线。**

新增 `Core.statusWithPlatform()`：平台自带在线标志是 `1`、我们却一条数值都没读到 → 判 `blank`（采集异常），
并在展开区写一行原因（`DevState.note`）。三种情况分开说：平台限流 / 没权限 / 网络不通。
截图上也一样 —— `Renderer.render()` 多了 `noteOverride` 参数，把「平台限流，这轮没取到数值」直接印在图上，
不再只写「未能读取到变量数据」让人以为站点坏了。

**三、巡站页可以只补跑没数据的站点。**

`Core.startPatrol(names, onlyEmpty)`：上一轮结果留作底稿（`baseResults`），
`onlyEmpty = true` 时只跑状态是 `offline` / `blank` / `error` 的那几台，跑完把新结果盖回底稿。
没得跑时 `startPatrol` 返回一句原因，前端原话显示。补跑只报这一轮，不混上一轮的「在线台数」。

**四、截图弹窗里能单张重拍。**

`Core.reshootStart()` 只起线程立刻返回，前端每 600 ms 轮询 `reshootPoll()` ——
同步等网络会把界面冻住（v0.37 的教训）。桥接新增 `reshootStart` / `reshootPoll` 两个 case，
结果里带上设备编号 `no`（站名会重名、会被改，靠名字定位不准）。

**五、巡站页的「选择站点」弹窗换成一个搜索框。**

设备一多，勾选弹窗里翻半天。现在结果列表上方是搜索框，输入即按站名/编号模糊筛，
台数跟着变成「2 / 22」，筛选状态放在模块级 `kwPatrol`，补跑、单张重拍、切页回来都还留着。
`devices` 接口暂时没有前端调用，排序逻辑保留（以后加任何选设备入口都要和监控页同序）。

### v0.38 新增

**单台刷新改成「后台跑 + 轮询」，弱网下不再冻界面。**

前端 `api()` 走 `Android.call`，是**同步**调用：Java 不返回，JS 线程就一直被占着，页面一帧都画不出来。
而单台刷新这条链要串登录 + 元信息 + 变量点 + 最新值（最多 4 个请求），弱网下每个连接/读取各 30 秒，
极端情况能卡住一两分钟——连「刷新中…」都来不及画，用户看到的就是「点一下，整个界面死掉」。

现在拆成两半：

- `Watch.refreshDeviceStart()`：只起后台线程立刻返回 `{ok, running}`。同一台正在跑就复用，
  不叠加线程；`REFRESH_POOL` 两条线程，`refreshDone` 存结果，`refreshRunning` 防重入，
  起跑时刻 `refreshAt` 用来清掉 10 分钟没人取的结果。
- `Watch.refreshDevicePoll()`：取结果，**取一次就删**（否则下一轮会先读到上一轮的旧数据）；
  还在跑就返回 `running:true`。

前端 `fetchDevAsync()` 每 400ms 问一次，`REFRESH_GIVEUP_MS = 30000` 到点先松手，
后台线程继续跑、结果写进快照，下次进来能看到。「刷新这台」和单变量刷新都走这条路。

**刷新中不抢提示格。** `REFRESHING[设备号|账号]` 记着谁在刷：`varsBody()` 画成
「正在读取…已等 N 秒」且按钮禁用，`patchDevList()` 的就地更新也认它——
否则 3 秒一轮的软刷新会把刚写下的「已等 N 秒」和超时原因当场冲掉。

**失败原因分开说。** `netMsg()` 按异常类型给话：读取超时（信号弱）/域名解析不了/
连不上服务器/安全连接没建立（可能被代理劫持），不再一律「刷新失败」。

### v0.34 新增

**截图卡片里水温变量排到最前。** 每台设备只画前 `Core.MAX_CARDS`（10）个变量，顺序原本是
平台返回的原始顺序 —— 平台那边是「谁先建的变量谁在前」。一台 17 个变量的热泵机组，
前十个位置常被 `水流量`、`定时运行使能`、`启动信号`、`T1修正` 占满，

现在渲染前先按「水温优先」重排再截断，分三档（同档内稳定排序，保持平台原顺序）：

| 档 | 判据 | 例子 |
| --- | --- | --- |
| 0 · 水温 | 名字里**既有「水」又有温度字样** | 供水温度T1、回水温度T2、水温、水箱温度、循环水温度 |
| 1 · 其它温度 | 名字里有「温度」或以「温」结尾 | 室内温度T3、室外温度T4、湿度 |
| 2 · 其余 | 以上都不是 | 水流量、循环泵出口压力、定时运行使能 |

三个细节：**先排序再截断**（否则水温早在第 11 位被扔掉，等于没改）；**只看变量名不看单位**；
**设定值和工程参数不算水温**（`水温设定`、`制冷停止温度`、`T1修正` 都留在原位，
`水流量` 只有水没有温也不进第 0 档）。

排序抽成零依赖纯类 `ShotOrder`，`jshotordertest` 跑真代码 **41 项全过**；

顺带修掉渲染循环遇到空壳行跳过不补位、导致少画一张卡片的问题。

### v0.33 修复

- **编辑账号表格时所有账号挤成一行**：Java 侧那个逐行读文件的函数读完整行**不拼换行符**，

  两个参数、从不读 `tab`，就算补上跳转也只会停在用户上次待的页签。

- **把变量全点掉后又弹回默认 3 条**：区分了「刚查出来还没动过」（兜底前 3 条）

- **巡检间隔设置后丢失（覆盖更新回到 15 分钟）**：设置间隔时只改了内存里的值、
  从头到尾没写盘。现在立刻写入应用私有目录并在启动时读回，

  短按仍是展开/收起；手指滑动会取消长按，不会边滚边复制。
- **「⟳ 刷新这台」挪到右上角**：展开站点后，按钮从变量表下方挪到展开区顶部右侧，
  和数据时间同一排，变量多的站点不用滚到底才能找到。
- **单变量刷新**：变量表每行当前值后面多了个蓝色 ⟳，只刷这一个变量——
  只就地更新该行的值和数据时间，其它行不动、整卡不重绘、滚动位置不跳；
  结果写回内存快照，翻页回来不跳回旧值；平台这次数据里没有该变量时会如实说明。

### 同版本修订

- **2026-10-18（版本号仍为 0.33，同日第二轮）**：修「15 分钟的周期跑成 19 分钟」。

  两个「多久之前」含义不同，不该互相印证：**数据年龄**（站点行首那句）是平台那版数据的
  时间戳，平台何时更新不由本机节拍决定，可以比一轮周期长；**巡检间隔**（上次巡检）
  必须守住用户设的数字。19 > 15，超的是后者。

  根因一，周期里混进了本轮用时：原来用 `scheduleWithFixedDelay`，下一拍 =
  本轮**跑完** + 间隔，于是一轮跑 4 分钟、设 15 分钟就变成 19 分钟。现在每轮结束后
  自己算下一拍（`ScanClock.nextDelaySec` = 间隔 − 本轮用时，最少留 30 秒），
  让「本轮开始 → 下轮开始」贴合设定值；停掉再开启会作废旧的那条链（代次号），
  不会两条链同时跑。

  根因二，后台/锁屏时轮次被推迟且回前台不补跑：本轮结束到现在已满一个间隔时，
  回到前台立刻补跑一轮（`Watch.catchUpIfOverdue`），不干等下一拍。

  界面跟着改明白：「上次巡检」后面直接写「（19 分钟前）」，不用再跟状态栏对时；
  真超期时提示把两个数都写出来（已 19 分钟 / 你设的 15 分钟周期）；
  没超期不提示，留 60 秒余量避免几秒抖动就弹。**只写算得出的事实**，
  不写「被系统推迟」这类没有当场证据的原因 —— 原因在日志页查。

  两个判定抽成零依赖纯函数 `ScanClock`，`jscanclocktest` 跑真代码 24 条边界全过。
- **2026-10-18（版本号仍为 0.33）**：三件事一起进。

  **一、历史数据能导出了，云端来源移除。** 「历史文件」弹窗原来只有删除，
  数据只能进不能出。现在补上导入 / 导出：导出沿用勾选语义走系统分享，
  导入走 SAF 文件选择器，三道关（超 512MB 拒 / 表头必须含「时间」「变量」/
  一律存成带时间戳的新文件、绝不覆盖已有）。同时**删掉「平台云端」数据来源**——
  `history.usr.cn:7002` 的 `historyData` 接口实测 404（平台已下线），
  新控制台的多曲线接口属于另一套设备体系、本账号设备不在其中。留着只会点了没反应。

  **二、「多久之前」不再冻住。** 行首的「刚刚 / N 分钟前」原来是后端巡检那一刻
  算好的静态字符串（`age_text = fmtAge(age_min)`），两轮轮询之间不会自己走：
  10:39 巡检算出「刚刚」，到 10:43 还写着「刚刚」，跟展开后的「数据时间 10:39」
  自相矛盾。现在改为**用 `data_time` 现算**，并挂 30 秒的自适应 `setTimeout` 链
  让文案自己往前走；离开监控页就停，不空转。**只动这一句文案，不动状态色块**——
  在线/陈旧/离线的阈值在后端，前端擅自改判定会和用户设的「陈旧判定阈值」对不上。

  **三、「我的 → 关于」加 GitHub 项目地址入口。** 走 `Android.openUrl` 桥交给
  系统浏览器打开，不用 `<a href>`：WebView 里直接跳过去会变成一个没有地址栏的
  浏览器，用户既回不去也没法复制链接。桥上只放行 `http/https`，参数来自网页，
  不能直接丢给 `Intent`（`javascript:` / `file:` / `intent:` 会被系统当命令执行）。
  另加了 `shouldOverrideUrlLoading` 兜底，以后网页里出现别处链也一律走浏览器。
- **2026-10-17（版本号仍为 0.33）**：修「常驻通知被规则命中带跑」。
  `PendingIntent` 判等**不看 extras**，只比 `requestCode + action + data + type + component`；
  常驻通知写死 `requestCode 1001`、提醒通知的 seq 首条恰好也是 1001，
  两边又都不设 action、都指向 `MainActivity` —— 在系统眼里是同一条。
  配合 `FLAG_UPDATE_CURRENT`，第一条规则命中就把常驻通知的点击目标改写成了那台设备。
  现在两边各带独有 action（`OPEN_WATCH` / `OPEN_ALERT`），常驻通知用 `requestCode 9002`，
  并且它的 Intent **只带 tab**、永远不放 `dev`/`acc`。
- **2026-10-15（版本号仍为 0.32）**：修「设置巡检间隔后界面不刷新」。
  原来设完直接调 `renderWatch()`，渲染的是内存里的旧快照，
  分段控件高亮和「启动后每 X 自动巡检一次」的文案都停在旧值，
  要切到别的页再切回来才更新；改为先 `pollWatch(true)` 重拉状态再重绘。

## 二、编译

前置：JDK 17、Android SDK（compileSdk 34）。Gradle 不用装，仓库自带 Wrapper（8.7）。

```bash
# 告知 SDK 位置（该文件不入库）
echo "sdk.dir=/path/to/Android/sdk" > local.properties      # macOS / Linux
echo sdk.dir=C:\\path\\to\\Android\\sdk  > local.properties # Windows

# 构建
./gradlew assembleRelease          # macOS / Linux
build.bat assembleRelease          # Windows（自动探测 JDK 与 SDK）
```

首次运行 Wrapper 会下载 Gradle 8.7（约 120 MB），之后走缓存。
`build.bat` 依次从 `JAVA_HOME` / `ANDROID_SDK_ROOT`、`TC` 环境变量、
常见安装位置、`local.properties` 里探测工具链，找不到会明确报错而不是静默失败。

### 签名

仓库**不含签名密钥**。没有密钥时 `build.gradle` 自动回落到 debug 签名，
保证 clone 下来就能打出可安装的包。要发布自己的版本，请自建密钥：

```bash
keytool -genkeypair -v -keystore keystore/usrcloud.jks -keyalg RSA -keysize 2048 \
        -validity 10950 -alias usrcloud -storepass <密码> -keypass <密码>
```

密码不要写进仓库，可用环境变量传入：

```bash
set USRCLOUD_STORE_PWD=xxx
set USRCLOUD_KEY_PWD=xxx
```

### 版本号怎么改

三处必须同步，改一处会不一致：

| 位置 | 字段 |
| --- | --- |
| `app/build.gradle` | `versionCode` / `versionName` |
| `app/src/main/java/…/Core.java` | `APP_VERSION`（界面「关于」读的是这个） |
| `app/src/main/assets/index.html` | `<span class="ver" id="hver">` |

另外 `_me.js` 里 `h.version || '0.39'` 是版本读不到时的兜底串，一起改。

## 四、注意

- 锁竖屏
- 巡站时尽量别切走太久，系统可能回收后台进程
- 包名是 `org.usrcloud.xunjian`，与其他包不同，**无法覆盖安装**别的包
- 「单台刷新」「单变量刷新」都只影响该站点，不会改变整体「上次巡检」时间戳
- 平台对同一用户有线频（官方口径 100 次/10 秒），正常手动操作远达不到
