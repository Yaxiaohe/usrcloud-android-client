# 有人云巡站（Android）

[有人云](https://www.usr.cn) 平台的第三方 Android 客户端：批量巡检设备、
自动截图归档、离线/数据陈旧告警、历史数据折线图。纯原生 Java + WebView，
APK 约 1.5 MB。

当前版本 **v0.33**（与 `versionName` / 界面「关于」页显示一致）。

> 本仓库是**干净版本**：`assets/accounts.csv` 只有表头，不含任何账号、密码、
> 登录缓存或巡检数据，也不含任何公司标识。装好后在「账号」页自己添加账号。

## 一、功能

- **巡站**：按账号批量拉取设备最新值，Android Canvas 直接画卡片图，4 路并发，约 0.3 s/台
- **状态判定**：`online` 数据新鲜 / `stale` 有值但过旧 / `offline` 无数据 / `blank` 采集异常
- **监控**：前台服务保活，按规则比对并推通知，离线/恢复都提醒，重复告警去重
- **历史**：自动采样落盘（值变了才写，稳定期 1 小时一次心跳），可查 6/24 小时折线
- **导出**：跑完自动打包 zip，走系统分享面板发出去
- **账号**：账号表可界面编辑，也可直接改原始 CSV

### v0.33 新增

- **异常提醒规则可以起名字**：规则编辑里「类型」上面多了一个「规则名称」输入框
  （选填，最长 30 字）。填了名字，通知标题就显示成 `规则名 · 设备名`，
  一屏又长又像的设备名里一眼能认出是哪条规则报的；app 内的提醒列表和规则列表
  也同步显示这个名字。**不填则完全沿用旧行为**，老规则不受影响。
- **「不在区间内」判定**（反向介于）：条件里新增这一项，值**掉出区间**才提醒。
  以前这种判断只能建两条规则（小于 8、大于 30），一次故障出两条提醒、冷却期还各算一份；
  现在一条规则搞定。两个框填反了会自动纠正，和「介于」一样。
- **温度类变量排到最前**：历史页变量顺序原本按「记录里第一次出现的先后」，
  一台 17 个变量的机组，出/回水温度常常要往下翻甚至掉出「只列前 60 个」的截断范围。
  现在变量名里带「温度 / temp / ℃ / 度」的一律排到最前，温度组内部保持原有相对顺序。

### v0.33 修复

- **编辑账号表格时所有账号挤成一行**：Java 侧那个逐行读文件的函数读完整行**不拼换行符**，
  整个 CSV 被拼成一大坨，显示上是「一长条 + 共 0 个账号」，保存时还会被后端的按行校验拒掉，
  看着像「编辑不了」。现在一行一个账号，计数与真实行数一致，改完能正常保存。
- **点「巡站监控运行中」那条常驻通知没反应**：这条前台服务通知从来没挂点击跳转，
  系统对没挂跳转的常驻通知默认就是「什么都不发生」；顺带发现原生侧只读 `dev/acc`
  两个参数、从不读 `tab`，就算补上跳转也只会停在用户上次待的页签。
  现在点它直接打开 app 并落到监控页，标题也改成「巡站监控运行中 · 点此打开」。
- **历史页「亮的变量」和「画的曲线」对不上**：按钮高亮和画布曲线是两套各算各的逻辑
  （前者不截断、后者最多 6 条），一旦「一个都没勾选」的兜底状态被触发就可能不同步。
  现在抽出 `activeCurves()` 作为唯一口径，按钮、画布、图例三处全走它。
- **点「正在显示的变量」应该是关掉它，不是只剩它**：默认显示的 3 条只是兜底渲染结果，
  内部勾选状态其实是空的，点击时把「未选」翻成「已选」，曲线就从 3 条塌成 1 条。
  现在兜底显示的几条会真正记进内部状态，点击基于「当前实际显示哪些」来切换。
- **把变量全点掉后又弹回默认 3 条**：区分了「刚查出来还没动过」（兜底前 3 条）
  和「已经动过、主动全关」（一条都不显示）两种空状态，画布会明确提示未选择变量。
- **巡检间隔设置后丢失（覆盖更新回到 15 分钟）**：设置间隔时只改了内存里的值、
  从头到尾没写盘。现在立刻写入应用私有目录并在启动时读回，
  读到的值还会校验（非数字或超 1 分钟~24 小时就删掉坏文件用默认值）。

### v0.32 新增

- **长按站名直接复制**：监控页设备列表里长按站名约半秒，完整站名进系统剪贴板。
  复制的是完整原文；复制完设备行不会跟着展开（长按抬起的那次点击会被吞掉）；
  短按仍是展开/收起；手指滑动会取消长按，不会边滚边复制。
- **「⟳ 刷新这台」挪到右上角**：展开站点后，按钮从变量表下方挪到展开区顶部右侧，
  和数据时间同一排，变量多的站点不用滚到底才能找到。
- **单变量刷新**：变量表每行当前值后面多了个蓝色 ⟳，只刷这一个变量——
  只就地更新该行的值和数据时间，其它行不动、整卡不重绘、滚动位置不跳；
  结果写回内存快照，翻页回来不跳回旧值；平台这次数据里没有该变量时会如实说明。

### 同版本修订

- **2026-10-18（版本号仍为 0.33，同日第二轮）**：修「15 分钟的周期跑成 19 分钟」。

  两个「多久之前」含义不同，不该互相印证：**数据年龄**（站点行首那句）是平台那版数据的
  时间戳，平台何时更新不由本机节拍决定，可以比一轮周期长；**巡检间隔**（上次巡检）
  必须守住用户设的数字。19 > 15，超的是后者。

  根因一，周期里混进了本轮用时：原来用 `scheduleWithFixedDelay`，下一拍 =
  本轮**跑完** + 间隔，于是一轮跑 4 分钟、设 15 分钟就变成 19 分钟。现在每轮结束后
  自己算下一拍（`ScanClock.nextDelaySec` = 间隔 − 本轮用时，最少留 30 秒），
  让「本轮开始 → 下轮开始」贴合设定值；停掉再开启会作废旧的那条链（代次号），
  不会两条链同时跑。

  根因二，后台/锁屏时轮次被推迟且回前台不补跑：本轮结束到现在已满一个间隔时，
  回到前台立刻补跑一轮（`Watch.catchUpIfOverdue`），不干等下一拍。

  界面跟着改明白：「上次巡检」后面直接写「（19 分钟前）」，不用再跟状态栏对时；
  真超期时提示把两个数都写出来（已 19 分钟 / 你设的 15 分钟周期）；
  没超期不提示，留 60 秒余量避免几秒抖动就弹。**只写算得出的事实**，
  不写「被系统推迟」这类没有当场证据的原因 —— 原因在日志页查。

  两个判定抽成零依赖纯函数 `ScanClock`，`jscanclocktest` 跑真代码 24 条边界全过。
- **2026-10-18（版本号仍为 0.33）**：三件事一起进。

  **一、历史数据能导出了，云端来源移除。** 「历史文件」弹窗原来只有删除，
  数据只能进不能出。现在补上导入 / 导出：导出沿用勾选语义走系统分享，
  导入走 SAF 文件选择器，三道关（超 512MB 拒 / 表头必须含「时间」「变量」/
  一律存成带时间戳的新文件、绝不覆盖已有）。同时**删掉「平台云端」数据来源**——
  `history.usr.cn:7002` 的 `historyData` 接口实测 404（平台已下线），
  新控制台的多曲线接口属于另一套设备体系、本账号设备不在其中。留着只会点了没反应。

  **二、「多久之前」不再冻住。** 行首的「刚刚 / N 分钟前」原来是后端巡检那一刻
  算好的静态字符串（`age_text = fmtAge(age_min)`），两轮轮询之间不会自己走：
  10:39 巡检算出「刚刚」，到 10:43 还写着「刚刚」，跟展开后的「数据时间 10:39」
  自相矛盾。现在改为**用 `data_time` 现算**，并挂 30 秒的自适应 `setTimeout` 链
  让文案自己往前走；离开监控页就停，不空转。**只动这一句文案，不动状态色块**——
  在线/陈旧/离线的阈值在后端，前端擅自改判定会和用户设的「陈旧判定阈值」对不上。

  **三、「我的 → 关于」加 GitHub 项目地址入口。** 走 `Android.openUrl` 桥交给
  系统浏览器打开，不用 `<a href>`：WebView 里直接跳过去会变成一个没有地址栏的
  浏览器，用户既回不去也没法复制链接。桥上只放行 `http/https`，参数来自网页，
  不能直接丢给 `Intent`（`javascript:` / `file:` / `intent:` 会被系统当命令执行）。
  另加了 `shouldOverrideUrlLoading` 兜底，以后网页里出现别处链也一律走浏览器。
- **2026-10-17（版本号仍为 0.33）**：修「常驻通知被规则命中带跑」。
  `PendingIntent` 判等**不看 extras**，只比 `requestCode + action + data + type + component`；
  常驻通知写死 `requestCode 1001`、提醒通知的 seq 首条恰好也是 1001，
  两边又都不设 action、都指向 `MainActivity` —— 在系统眼里是同一条。
  配合 `FLAG_UPDATE_CURRENT`，第一条规则命中就把常驻通知的点击目标改写成了那台设备。
  现在两边各带独有 action（`OPEN_WATCH` / `OPEN_ALERT`），常驻通知用 `requestCode 9002`，
  并且它的 Intent **只带 tab**、永远不放 `dev`/`acc`。
- **2026-10-15（版本号仍为 0.32）**：修「设置巡检间隔后界面不刷新」。
  原来设完直接调 `renderWatch()`，渲染的是内存里的旧快照，
  分段控件高亮和「启动后每 X 自动巡检一次」的文案都停在旧值，
  要切到别的页再切回来才更新；改为先 `pollWatch(true)` 重拉状态再重绘。

## 二、编译

前置：JDK 17、Android SDK（compileSdk 34）。Gradle 不用装，仓库自带 Wrapper（8.7）。

```bash
# 告知 SDK 位置（该文件不入库）
echo "sdk.dir=/path/to/Android/sdk" > local.properties      # macOS / Linux
echo sdk.dir=C:\\path\\to\\Android\\sdk  > local.properties # Windows

# 构建
./gradlew assembleRelease          # macOS / Linux
build.bat assembleRelease          # Windows（自动探测 JDK 与 SDK）
```

首次运行 Wrapper 会下载 Gradle 8.7（约 120 MB），之后走缓存。
`build.bat` 依次从 `JAVA_HOME` / `ANDROID_SDK_ROOT`、`TC` 环境变量、
常见安装位置、`local.properties` 里探测工具链，找不到会明确报错而不是静默失败。

### 签名

仓库**不含签名密钥**。没有密钥时 `build.gradle` 自动回落到 debug 签名，
保证 clone 下来就能打出可安装的包。要发布自己的版本，请自建密钥：

```bash
keytool -genkeypair -v -keystore keystore/usrcloud.jks -keyalg RSA -keysize 2048 \
        -validity 10950 -alias usrcloud -storepass <密码> -keypass <密码>
```

密码不要写进仓库，可用环境变量传入：

```bash
set USRCLOUD_STORE_PWD=xxx
set USRCLOUD_KEY_PWD=xxx
```

### 版本号怎么改

三处必须同步，改一处会不一致：

| 位置 | 字段 |
| --- | --- |
| `app/build.gradle` | `versionCode` / `versionName` |
| `app/src/main/assets/index.html` | `<span class="ver" id="hver">` |

## 三、数据存哪

| 数据 | 位置 |
| --- | --- |
| 账号表 | `/data/data/org.usrcloud.xunjian/files/accounts.csv` |
| 巡站截图 | `.../files/巡站截图/<批次>/<账号名>/*.png` |
| 导出 zip | `/storage/emulated/0/Android/data/org.usrcloud.xunjian/files/` |
| 历史数据 | `.../files/历史数据_YYYY-MM.csv` |
| 登录缓存 | `.../files/登录缓存/` |

截图写在应用私有目录，所以 Android 11+ 不需要「所有文件访问权限」；
导出走系统分享面板，可另存到「文件」或发给自己。

## 四、注意

- 锁竖屏
- 巡站时尽量别切走太久，系统可能回收后台进程
- 包名是 `org.usrcloud.xunjian`，与其他包不同，**无法覆盖安装**别的包
- 「单台刷新」「单变量刷新」都只影响该站点，不会改变整体「上次巡检」时间戳
- 平台对同一用户有线频（官方口径 100 次/10 秒），正常手动操作远达不到
